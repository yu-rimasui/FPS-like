# 業務設計書

本書は「FPSごっこ」のiOSゲームMVPの開発範囲を定義する。現在の成果物はHTMLによる静的UIモックであり、本書に記載するゲーム機能は未実装。

## 1. システム概要

FPS未経験者でも、敵に撃たれることなくFPSの操作感を体験できるiOS向けカジュアルゲームを提供する。

ゲーム音痴の姉に、弟が「敵全部倒しといたから。」と渡した訓練場が舞台。敵は最初から全員倒れており、プレイヤーは移動・視点操作・射撃・リロードといった「FPSやってる感」を安心して楽しめる。

敵AIやゲームオーバーは設けない。リアルな戦争や恐怖、流血表現を避け、姉弟の掛け合いとコミカルな反応を楽しむ。1回のプレイ時間は1〜3分を想定する。

## 2. 開発目的

- SpriteKitを用いたゲーム開発を学習する。
- 小規模なゲームを最後まで完成させる。
- 「FPSごっこ」という独自コンセプトを形にする。

## 3. 対象ユーザー

- FPSに興味はあるが難しい、怖いと感じている人。
- FPSの雰囲気や操作感だけを楽しみたい人。
- 短時間で気軽に遊べるゲームを求める人。

## 4. 業務範囲（MVP）

### 対象

- タイトル・ゲーム・リザルトの3画面。
- 移動、視点操作、射撃、リロード。
- 武器変更UI（MVPでは武器1種類でも可）。
- FPS風HUD、スコア、タイマー、照準。
- 倒れた対象への命中判定とラグドール物理演算による反応。
- 命中率・コンボの集計と結果表示。
- 制限時間終了、再プレイ、タイトルへの復帰。
- リザルトでの姉弟の掛け合い。

### 対象外

- セーブデータ、ランキング、ログイン、アカウント。
- オンライン対戦、マルチプレイ、API、バックエンド。
- 敵AI、ゲームオーバー。
- ステージ選択、実績、スキン、武器収集。
- 課金、広告。
- 独立した導入画面・設定画面など、3画面以外の追加。

設定ボタンはプレースホルダーとし、設定項目は追加しない。現在のUIモックではゲーム描画・ゲームロジックを実装せず、中央の「GAME VIEW」と固定値のHUDでデザインのみ確認する。

## 5. 業務フロー

1. アプリ起動。
2. タイトル画面表示。
3. START選択。
4. スコア・命中率・コンボ・タイマーを初期化してゲーム開始。
5. プレイヤーが自由に移動・視点操作・射撃・リロードを行う。
6. 制限時間終了。
7. リザルトでスコア・命中率・コンボと姉弟の掛け合いを表示。
8. Play Againで新しいプレイを開始、またはタイトルへ戻る。

## 6. 画面一覧

| 画面 | 概要 | 主な表示・操作 |
| --- | --- | --- |
| Title | ゲーム開始 | FPSごっこ、サブタイトル、START、設定プレースホルダー |
| Game | FPS操作・射撃 | ゲーム領域、移動、射撃、リロード、武器変更、スコア、タイマー、照準 |
| Result | 結果表示 | Mission Complete、姉弟の掛け合い、スコア、命中率、コンボ、Play Again、タイトルへ戻る |

現行モックは3画面を横並びで表示し、画面遷移は行わない。「タイトルへ戻る」は今後のiOS実装時にリザルト内へ配置する。

## 7. 機能一覧

### タイトル

- ゲームタイトル「FPSごっこ」とサブタイトル「弟が全部倒しといたから。」を表示する。
- STARTでゲームを開始する。
- 設定ボタンは表示のみとする。

### ゲーム

- 左下のジョイスティックで移動する。
- ゲーム領域のスワイプで視点を操作する。
- 右下の射撃ボタンで発射する。
- リロードで弾数を回復する。
- 武器変更UIを配置する。武器1種類の場合は変更処理を行わない。
- スコア・残り時間・照準を表示する。
- 対象への命中に応じて加点し、倒れた対象が物理演算で少し動く。
- 命中率と最大コンボを集計し、制限時間終了後に結果へ渡す。

加点量、コンボ継続条件、制限時間、弾数はゲーム実装前に決定する。命中率は命中数 ÷ 発射数とし、未発射時は0%とする。モックの数値は仕様値ではない。

### リザルト

- 「Mission Complete」を表示する。
- 次の掛け合いを表示する。
  - 弟「どうだった？」
  - 姉「FPSやった！」
  - 弟「敵全部倒したの俺だけどね。」
- スコア・命中率・最大コンボを表示する。
- Play Againでプレイ状態を初期化して再開する。
- タイトルへ戻れるようにする。

## 8. 非機能要件

以下はiOS MVPの目標であり、現時点では未検証。

- オフライン動作・ローカル完結。
- 60FPSを目標とする。
- 起動から5秒以内にゲーム開始可能な状態にする。
- シンプルで判読しやすく、操作しやすいUIとする。
- 可愛い・ゆるい・現代風レトロを基調とし、余白、四角いUI、ドット感、ピクセルアイコンを重視する。
- ボタンの角丸を使わず、影と立体感は最小限にする。

対象端末・対応OS・性能計測条件はiOSプロジェクト作成時に決定する。現行HTMLモックは固定サイズで、Tailwind CSSとWebフォントの読み込みにネット接続を要するため、iOS版のオフライン要件を満たした成果物とは扱わない。

## 9. 開発方針

- Swift・SwiftUI・SpriteKit・Xcodeを用い、iOS MVPでは外部ライブラリを追加しない方針とする。
- Phase単位で開発し、各Phaseで動作確認を行う。
- スコープ外の実装を行わず、MVP完成を最優先にする。
- Button・Card・HUD・Dialog・Panelの単位でUIを整理し、SwiftUIへの移植に活用する。

| Phase | 内容 | 確認内容 |
| --- | --- | --- |
| 1：UI設計（現在） | HTML・Tailwind CSSによる3画面の静的モック | 配色、余白、文字、HUD配置を確認 |
| 2：操作・物理の試作 | iOS上でFPS風の見せ方、移動・照準・射撃・ラグドール反応を最小構成で確認 | 採用する表現と操作がコンセプトに合うことを実機で確認 |
| 3：MVP統合 | 3画面の遷移、リロード、スコア集計、時間終了、再プレイ | 起動から再プレイまで通して確認 |
| 4：仕上げ | UI・演出・性能の調整 | 完了条件と非機能要件を実機で確認 |

SpriteKitでのFPS風表現とラグドールの具体的な方式は未決定。Phase 2で成立性を確認してから本実装へ進む。技術変更が必要な場合は本書とREADMEの方針を更新する。

## 10. 完了条件（MVP）

以下をすべて満たした時点でMVP完成とする。静的モックの完成とは区別する。

- [ ] タイトル画面が表示できる。
- [ ] STARTからゲーム画面へ遷移できる。
- [ ] FPS風HUDが表示される。
- [ ] 移動・視点操作・射撃・リロードができる。
- [ ] 武器変更UIが表示される（1種類の場合は変更なしで可）。
- [ ] 命中した対象のラグドール物理演算が動作する。
- [ ] 射撃結果に応じてスコア・命中率・コンボが集計される。
- [ ] 制限時間終了でリザルトへ遷移し、結果と掛け合いが表示される。
- [ ] Play Againで前回の状態を引き継がず再プレイできる。
- [ ] リザルトからタイトルへ戻れる。
- [ ] 敵の攻撃・ゲームオーバーが発生しない。
- [ ] 実機でオフライン動作と性能目標を確認できる。
